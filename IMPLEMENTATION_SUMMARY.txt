ARCHITECTURE & DESIGN
================================================================================

DATA STRUCTURES:

ProductGraph (Graph-based structure)
├── Nodes: Products
├── Edges: Co-purchase relationships (weighted by frequency)
├── Indexing: Category-based for O(k) lookups
├── Time Complexity:
│   ├── Add product: O(1)
│   ├── Add edge: O(1)
│   ├── Get neighbors: O(degree)
│   ├── Get edge weight: O(1)
│   └── Category search: O(k)
└── Space Complexity: O(V + E)

ALGORITHMS:

Apriori Algorithm (Frequent Itemset Mining)
├── Principle: Prune search space using Apriori Principle
├── Steps:
│   1. Find frequent 1-itemsets
│   2. Generate (k+1)-candidates from k-itemsets
│   3. Prune candidates not meeting min_support
│   4. Repeat until no new frequent itemsets
├── Time Complexity: O(2^m * n) → O(n*k) with pruning
├── Space Complexity: O(2^m)
└── Pruning Efficiency: ~95% candidate elimination

Association Rules Mining
├── Generate all antecedent-consequent pairs
├── Calculate metrics:
│   ├── Support: P(A ∩ B)
│   ├── Confidence: P(B|A)
│   └── Lift: P(A ∩ B) / (P(A) * P(B))
├── Filter by confidence threshold
└── Rank by lift


KEY DESIGN DECISIONS & JUSTIFICATION
================================================================================

1. PRODUCT GRAPH vs ALTERNATIVES
 Chosen: Graph structure (adjacency list)
 Justification: Natural domain modeling, O(1) lookups
 Rejected: Matrix representation (inefficient for sparse graphs)
 Rejected: Tree structure (doesn't capture all relationships)

2. APRIORI vs ALTERNATIVES
 Chosen: Apriori algorithm with pruning
 Justification: Industry standard, proven effective, good pruning
 Rejected: Eclat (more complex, similar results)
 Rejected: K-means (different problem domain)
 Deferred: FP-Growth (future optimization, 50-100x faster)

3. SET-BASED TRANSACTIONS
 Chosen: frozenset for immutability and hashing
 Justification: O(1) membership tests, natural set operations
 Alternative: List (O(n) membership tests)

4. DICTIONARY-BASED CACHING
 Chosen: Hashmap for frequency and edge weights
 Justification: O(1) updates and lookups
 Alternative: Array-based (slower lookups)
